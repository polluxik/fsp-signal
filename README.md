# ФСП Сигнал — рабочий прототип

Веб-прототип обратного найма по [спецификации](docs/PRODUCT_SPEC.md). Компания ищет кандидата по категории, присвоенной тестом, и первой направляет приглашение с зарплатой. Контакты открываются только компании, приглашение которой кандидат принял.

Работодатель может возвращаться к сохранённым подборкам после обновления страницы и уточнять поиск от предыдущей подборки. Если кандидат снимет профиль с публикации, в старом результате его карточка больше не показывается.

Кандидат может заполнить профиль вручную или загрузить PDF-резюме с текстовым слоем. Импорт показывает черновик полей; исходный PDF не сохраняется, профиль не публикуется до отдельного сохранения и согласия. Скан без текстового слоя пока не распознаётся.

**Статус:** код стартового прототипа. Главный API-сценарий проверен автоматическим тестом и пройден в локальном браузере; публичный деплой, пилот с реальными пользователями, метрики качества ранжирования и реальная интеграция ФСП не выполнены. Подробное покрытие — в [статусе реализации](docs/implementation-status.md).

После интеграции ветки команды `codex/synthetic-market-seed`: **216 backend passed на PostgreSQL**, **203 passed / 13 PG-only skipped на SQLite**, **29 браузерных сценариев passed**, включая 3 live-Qwen; production build успешен. Compose работает на 58080, три тестовые встречи сохранены. Источники и следующие задачи — в [аудите Q&A](docs/hackathon-requirements-audit.md), [плане функций](docs/REFERENCE_FEATURE_PLAN.md) и [передаче участнику](docs/next-agent.md).

«Рынок · демо» содержит **200 полных резюме и 120 вакансий по 32 направлениям**. HR читает CV, фильтрует примеры и сравнивает заявленные условия; кандидат смотрит вакансии. Это вымышленные, неоценённые персонажи: они не попадают в проверенный банк из 96 учебных assessment-профилей и не получают грейд, контакты или приглашения. Для обновления существующей демо-БД после миграций запускайте только `APP_MODE=demo python -m backend.seed_market`: повторный импорт не создаёт дублей. Полный [контракт и передача](docs/SYNTHETIC_MARKET_INTEGRATION.md).

На вкладке «Для меня» появился маршрут кандидата с причинами невидимости профиля и продолжением активного теста. Перед тестом показаны компетенции выбранной категории. После проверки и из истории доступен приватный разбор баллов по темам с упражнениями для подготовки. Проценты описывают конкретную попытку, а не вероятность найма.

HR видит воронку точной версии роли в «Найти специалиста» и сохраняет профили в «Избранные кандидаты». Список приватен, переживает перезагрузку, проверяет актуальные согласия и условия; конфликт двух вкладок не отменяет чужое действие. Прежние условия доступны в истории, реальные и синтетические данные разделены. Контракт и [что проверить после pull](docs/EMPLOYER_PIPELINE.md#что-проверить-участнику-после-pull) описаны для следующего агента.

Signal v2 включает версионированные карточки ролей, предпочтения и приватность кандидата, evidence, версию подбора `match_v2`, закрепление условий в приглашении и ленту актуальных ролей с сохранением/скрытием. Подтверждённое достижение ФСП хранится отдельным credential и даёт только ограниченный релевантный буст внутри категории, уже присвоенной тестом; отсутствие ФСП не штрафуется. Кандидат не отправляет отклик из ленты: основной контакт остаётся за работодателем. Фактическое покрытие — в [статусе](docs/implementation-status.md); основания решений и зарубежные аналоги — в [ресерче](docs/research/PRODUCT_RESEARCH.md).

Дополнительно реализованы календарь HR со слотами 20/30 минут и бронированием по ссылке, заметки/аудио/расшифровка встречи с согласиями, Qwen-итоги и карточки со свайпом и объяснимым процентом совпадения. Архитектура этого контура описана в [техническом документе](docs/CALENDAR_MATCH_ARCHITECTURE.md). Автоматический ASR требует отдельного speech-провайдера; chat API его не заменяет.

## Быстрый запуск через Docker Compose

Нужен работающий Docker Engine. Эта сборка рассчитана на локальную демонстрацию с синтетическими данными; веб-адрес привязан к `127.0.0.1`.

```powershell
docker compose up --build -d
docker compose run --rm api python -m backend.seed_demo
docker compose ps
```

Откройте `http://127.0.0.1:8080`. Почтовый ящик Mailpit — `http://127.0.0.1:8025`. Swagger — `http://127.0.0.1:8080/api/docs`, OpenAPI — `/api/openapi.json`.
Если порт 8080 занят или зарезервирован системой, перед запуском задайте `$env:FSP_WEB_PORT='58080'` и открывайте сайт, Swagger и ссылки из писем на `http://127.0.0.1:58080`. Значение порта задавайте в том же терминале, где вызываете `docker compose`.

Демо-работодатель: `employer@demo.test` / `DemoPass123!`. Второй работодатель: `other@demo.test` / тот же пароль. Seed создаёт 96 **синтетических** кандидатов (по 12 на категорию); любой из них входит по адресу вида `backend-middle-1@demo.test` и паролю `DemoPass123!`. Для настоящего прохождения теста зарегистрируйте нового кандидата, откройте письмо подтверждения в Mailpit и войдите.

Последовательность показа: работодатель создаёт/выбирает потребность → открывает подборку → отправляет приглашение → кандидат принимает → тот же работодатель видит контакты, другой не видит.

На текущем Windows 8 октября восстановлен Docker Engine 29.4.3 и поднят Compose `fsp-signal-smoke-20261007` на порту **58080**: PostgreSQL-миграция, API readiness, web, worker, Mailpit и точное совпадение OpenAPI с живым контрактом. Повторно проверены регистрация, доставка письма, ссылка на текущий порт, подтверждение email и вход. Предыдущий SQLite-демо-файл сохранён отдельно в workspace, данные в PostgreSQL автоматически не переносились. Процедура обхода сбоя Desktop — в [документе восстановления](docs/DOCKER_WINDOWS_RECOVERY.md). Публичный HTTPS-стенд и внешний SMTP ещё не проверены.

## Локальный запуск без контейнеров

Используйте Python 3.12 и Node.js, совместимый с зафиксированным Vite. Команды ниже — PowerShell из корня проекта.

```powershell
python -m venv .venv
& '.venv/Scripts/python.exe' -m pip install -r backend/requirements.txt
$env:APP_MODE='demo'
$env:DATABASE_URL='sqlite:///./fsp_signal.db'
$env:PUBLIC_BASE_URL='http://127.0.0.1:5173'
& '.venv/Scripts/alembic.exe' upgrade head
& '.venv/Scripts/python.exe' -m backend.seed_demo
& '.venv/Scripts/python.exe' -m uvicorn backend.main:app --host 127.0.0.1 --port 8000
```

В другом терминале:

```powershell
cd frontend
npm ci
npm run dev
```

Откройте `http://127.0.0.1:5173`. Для регистрации нового аккаунта потребуется SMTP на `localhost:1025`: можно поднять сервис `mailpit` из Compose после запуска Docker и отдельно запустить worker:

```powershell
& '.venv/Scripts/python.exe' -m backend.mail_worker
```

Без SMTP можно войти в заранее подготовленные синтетические аккаунты; подтверждение нового email в браузере не сработает, пока письмо не доставлено. Автоматический API-тест проверяет сам механизм подтверждения.

## Проверки

```powershell
& '.venv/Scripts/python.exe' -m pytest -q
& '.venv/Scripts/python.exe' scripts/simulate_assessment_validation.py
cd frontend
npm run build
npm run test:e2e
```

Для E2E нужен установленный Chrome и Python-окружение `.venv` в корне проекта (`Scripts/python.exe` на Windows, `bin/python` на Linux/macOS). Если окружение находится в другом месте, задайте `FSP_SIGNAL_E2E_PYTHON` как абсолютный путь к его интерпретатору. Playwright запускает API и Vite на случайных локальных портах в разных диапазонах, мигрирует временную SQLite и удаляет её после прогона.

Последняя итерация 8 октября: **216 passed на пустой выделенной PostgreSQL**, **203 passed / 13 PG-only skipped на SQLite**, полный Playwright **29 passed**, TypeScript/Vite production build. Миграция `c918e47a25bf`, повторный импорт и сохранность прежних данных проверены в текущем Compose. Swagger содержит 92 операции; live/export контракты совпадают. Корпус CV/вакансий воспроизведён генератором; [результаты интеграции](docs/validation/synthetic-market-integration-results.md). Synthetic assessment JSON тоже воспроизводится; [отчёт](docs/validation/assessment-synthetic-results.md) не заменяет человеческую калибровку. По просьбе не пересобирать Docker исходники API и готовая статика обновлены в существующих контейнерах, включая уточнение Qwen-инструкции. Это временное обновление контейнеров: при будущем пересоздании нужна сборка образов из актуального Git.

Актуальная сверка с ТЗ и официальной перепиской, включая точную трактовку API и список блокеров сдачи: [аудит требований хакатона](docs/hackathon-requirements-audit.md).

## Устройство

- `frontend/` — React, TypeScript, Vite; два кабинета.
- `backend/main.py` — HTTP API и серверные ограничения доступа.
- `backend/assessment.py`, `backend/assessment_qa.py`, `backend/assessment_data_analyst.py` — восемь версионированных тестовых категорий с параметрами и фиксированной рубрикой; ключи ответов остаются на сервере.
- `backend/resume_import.py` — извлечение черновика профиля из текстового PDF без хранения файла.
- `backend/matching.py` — фильтры, прозрачная формула, объяснения.
- `backend/evaluation.py`, `scripts/evaluate_matching.py` — воспроизводимый расчёт Precision@k, nDCG@k и межэкспертного quadratic weighted kappa.
- `backend/models.py`, `backend/migrations/` — SQLAlchemy и начальная Alembic-миграция.
- `backend/mail_worker.py` — SMTP-очередь на таблице БД.
- `backend/seed_demo.py` — синтетические данные, только для `APP_MODE=demo`.
- `infra/`, `compose.yaml` — контейнеры API, миграций, worker, PostgreSQL, Caddy и Mailpit.

На локальном dev используется SQLite; Compose использует PostgreSQL. Рекомендуемая конфигурация для публичного стенда потребует домен, HTTPS, действующие секреты, SMTP, отдельную политику хранения данных и проверку в реальной среде.

## Важные границы

API реестра ФСП организаторы не предоставили. Режим `mock` допустим только в демо; введённый произвольный ID помечается `unverified` и бонуса не даёт. Демо-кандидаты с баллами из seed помечены `synthetic_fixture`. Новый кандидат проходит evaluator платформы. Алгоритм тестов и поиск требуют отдельного экспертного и пользовательского пилота; файлы `data/evaluation/*.template.*` показывают только контракт и не являются результатом качества.
