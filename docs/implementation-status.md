## Следующий приоритет

1. Провести внешний rubric review и человеческий A/B pilot тестов: пока есть только автоматическая проверка форм.
2. Дать двум экспертам независимо разметить полный qrels по готовому blind-протоколу и сравнить `match_v2` без/с FSP-бустом с baseline; не представлять шаблон и synthetic fixture как измеренную релевантность.
3. Ввести workplace/company verification перед публичным пилотом, проверить PDF/import в браузере, защищённые/сканированные/большие PDF и внешний SMTP.
4. Собрать публичный стенд, презентацию по обязательному шаблону, резервное видео и PDF/DOC пакет; локальная Docker/PostgreSQL-проверка уже пройдена.
5. Подготовить release commit до дедлайна и режим доступа экспертов к репозиторию; после дедлайна не вносить функциональные изменения.

К 7 октября T1–T8 находятся в `main`: миграционно-управляемый runtime, immutable role versions и жизненный цикл, preferences с CAS, adult attestation, candidate-only compatibility, pair-wide block/revoke, приватные achievement stories и подтверждённые evidence, `match_v2` со снимками, закреплённые условия/evidence приглашения, UI работодателя и лента ролей кандидата с version-checked save/hide/undo. Полный Compose, доставка через Mailpit, PDF в Linux, 4 браузерных сценария и frontend build проверены. Внешний экспертный разбор rubric и пользовательский A/B не подменяются synthetic тестами.

## Дополнительные функции продуктового контура

В дополнительный продуктовый контур входят демонстрационные кампании продвижения. Кампания доступна только владельцу опубликованной, discoverable и свежей роли; хранит точную версию и 14-дневное окно. При показе снова проверяются зарплата, формат/город, доступность кандидата, блокировка компании и скрытие роли. Кандидатские впечатления и решения записываются минимальными событиями с дневной дедупликацией; работодатель не получает данные о сохранении/скрытии. В модели и API нет тарифа или оплаты; демонстрационная выручка всегда ₽0.

Историческая проверка этого блока: backend — 131 passed / 8 skipped (PostgreSQL-only); Playwright — 16 passed; TypeScript typecheck и production build прошли. Визуально просмотрены desktop-кабинет работодателя и mobile-лента кандидата. Интеграционные E2E используют контролируемый stub. Один live completion через внешний адаптер завершился `AI_PROVIDER_TIMEOUT` на 12-секундном лимите; TLS/HTTP smoke без авторизации подтвердил доступность gateway (`405` на GET), но не валидность ключа, модели или ответа. Платежных вызовов не выполнялось.
