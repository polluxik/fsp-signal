## Следующий приоритет

1. Провести внешний rubric review и человеческий A/B pilot тестов: пока есть только автоматическая проверка вариантов.
2. Проверить SMTP/Mailpit, PDF-паспорт в Linux и браузере, календарные границы и PostgreSQL races приглашений (7 тестов требуют PostgreSQL).
3. Разметить пары «потребность–кандидат» и сравнить `match_v2` с baseline; не представлять synthetic fixture как измеренную релевантность.
4. Уточнить P1 по пилотным данным и собрать публичный стенд, презентацию, видео и PDF/DOC пакет.

## Реализация Signal v2

К 7 октября T1–T8 находятся в `main`: миграционно-управляемый runtime, immutable role versions и жизненный цикл, preferences с CAS, adult attestation, candidate-only compatibility, pair-wide block/revoke, приватные achievement stories и подтверждённые evidence, `match_v2` со снимками, закреплённые условия/evidence приглашения, UI работодателя и лента ролей кандидата с version-checked save/hide/undo. Старый путь работодателя с историей подборок сохранён. Внешний экспертный разбор rubric, пользовательский A/B и PostgreSQL-only проверки не подменяются synthetic тестами. На Windows проверены 73 backend-теста, 4 браузерных сценария и frontend build; 7 PostgreSQL-only тестов пропущены без тестовой БД.
