# Передача участнику: PR #1, Q&A и новые функции

8 октября 2026. PR [#1](https://github.com/polluxik/fsp-signal/pull/1), commit `876c860`, уже слит в `main` через `2a6daab`. Большая часть 8 123 добавленных строк — экспорт OpenAPI; 76 файлов включают новые инструменты валидации и удаление старых внутренних планов. История удалённых документов сохранена в Git.

Полезные изменения PR: структурный provenance ФСП и evidence в приглашениях/паспорте, буст максимум +5 внутри подтверждённой категории, QA/Data Analyst в UI, параметризованные и перемешанные формы assessment, синтетическая test-retest симуляция, скрипты Precision@5/nDCG@5/kappa, OpenAPI cookie/CSRF/error contract, атомарная инициализация календаря.

После review исправлены:

- Для существующего календаря возвращена сериализация изменения настроек и проверки/добавления доступности. Атомарный initializer оставлен. PostgreSQL regression test параллельных диапазонов и весь набор гонок прошли на этой машине.
- Миграционный тест живых дублей больше не использует истёкшую 8 октября фиксированную дату. Ошибка была в тестовой фикстуре, не в автоматическом истечении приглашений.
- Lower-grade fallback после failed Middle не расходует квоту Junior. Смена подтверждённой категории всё равно требует успешного теста; повышение, другая специализация и повтор того же уровня не получают бесплатный обход ограничений.
- Сохранены оба источника Q&A; обязательные условия отделены от предложенных quality gates. Независимые эксперты и реальные кандидаты не объявляются обязательными. Исправлена Markdown-таблица synthetic отчёта.

Ссылки: [аудит](hackathon-requirements-audit.md), [архитектура календаря/материалов/карточек](CALENDAR_MATCH_ARCHITECTURE.md), [validation protocol](validation/v2-protocol.md), [статус](implementation-status.md).

По запросу пользователя изучен [SergeLyamin/fsp-talent](https://github.com/SergeLyamin/fsp-talent) на commit `3965f65`. Сначала записан [план переноса идей](REFERENCE_FEATURE_PLAN.md), затем реализованы три P0 функции: маршрут кандидата с серверной проверкой сохранённого состояния, план компетенций перед тестом, приватный разбор завершённой попытки и практические упражнения по пробелам. Resume доступен из маршрута, отчёт — после submit и из истории. Код: `backend/candidate_progress.py`, `frontend/src/features/progress/`, подключение в App/main. Новых таблиц, сторонних SDK и внешних AI-вызовов нет; чужой код и банк вопросов не копировались.

API: `GET /api/v1/candidate/journey` и `GET /api/v1/candidate/assessment-attempts/{id}/report`, оба типизированы и read-only. Последний закрыт от работодателя/другого кандидата, не отдаёт ключи, seed, задания или ответы. Проценты отражают конкретную попытку; отчёт не присваивает грейд и не меняет matching.

Что остаётся:

1. Следующий продуктовый этап — воронка HR по версии роли и приватный shortlist с актуальными visibility/block guards. Затем уточнения snapshot и CI. Подробные acceptance criteria и P1/P2 — в плане функций; не объявлять их реализованными по одному наличию документа.
2. Собрать собственный размеченный набор matching и сохранить результаты сравнения с baseline. Текущие qrels/rankings — шаблоны, а не результаты. Synthetic assessment report не подтверждает качество тестов на людях.
3. Для автоматической расшифровки нужен отдельный speech endpoint/model/key; Qwen chat включён только для текста. Полная запись видеозвонка автоматически не делается.
4. Подготовить презентацию, DOC/PDF документацию, доступный экспертам стенд либо видео. Основной путь доступен без GPU и внешней модели.
5. Дополнить response models: 51 JSON-success operation в OpenAPI пока имеет пустую schema. Security/errors и существующие response models документированы; не объявлять контракт полностью типизированным.

На текущем Windows Docker Desktop 4.74.0 восстановлен переименованием только служебной папки `Docker/run`, Engine 29.4.3 отвечает. Compose `fsp-signal-smoke-20261007` работает на `http://127.0.0.1:58080`, Mailpit — на 8025. Старый Vite на 58080 остановлен после проверки контейнерного стенда; отдельная SQLite база сохранена на диске, автоматического переноса её данных в PostgreSQL нет. Диагноз и процедура обхода — [DOCKER_WINDOWS_RECOVERY.md](DOCKER_WINDOWS_RECOVERY.md). После следующей перезагрузки устойчивость обхода ещё предстоит проверить. Том приложения не удалялся; одноразовый PostgreSQL-контейнер `*_test` остановлен после тестов. Не менять приватность репозитория и не публиковать материалы без отдельного запроса пользователя.

Проверки после исправлений и новых функций: **185 backend passed на PostgreSQL**, **175 passed / 10 PG-only skipped на SQLite**, 20 существующих и 2 новых браузерных сценария прошли; 3 live-AI skipped. Полный Playwright первоначально упал только на сравнении innerText/textContent нового теста; после исправления обе новые проверки прошли focused rerun. Production build, мобильный screenshot report, миграция/seed, readiness/login/journey и точное совпадение OpenAPI проверены. Сквозная регистрация: API → worker → Mailpit → ссылка с портом 58080 → подтверждение → вход прошла. Регистрация была реализована раньше. Реальные внешние AI-вызовы в этой итерации не выполнялись; автоматический ASR не подключён. Формула matching и synthetic демо-профили не менялись.
