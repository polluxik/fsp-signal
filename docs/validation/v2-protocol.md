# Signal v2: протокол независимой валидации

**Статус:** готовый протокол и исполняемый расчёт метрик. Для assessment выполнен отдельно помеченный [синтетический mechanics-only stress test](assessment-synthetic-results.md); человеческая калибровка и независимая matching-разметка ещё не получены.

## 1. Matching

1. Зафиксировать commit, версии алгоритмов и dataset hash.
2. Подготовить не менее 8 потребностей: по две на выбранную пару «специализация × грейд».
3. Для каждой потребности зафиксировать полный допустимый пул, а не только top-k.
4. Два эксперта независимо ставят метки 0–3 по рабочей задаче, подтверждённым компетенциям и обязательным условиям. Они не видят итоговый score, позицию, FSP-результат и метку второго эксперта.
5. До разметки разделить запросы на dev и holdout. После просмотра holdout веса не менять.
6. Сравнить keyword baseline, category+test, `match_v2` и `match_v2` с ограниченным FSP-бустом.

Основные метрики: Precision@5, nDCG@5, win/tie/loss по запросам и quadratic weighted kappa между экспертами. Запросы без релевантных кандидатов показывать отдельно. Короткая выдача не уменьшает знаменатель Precision@5.

Release gate: ноль нарушений hard constraints; на holdout новая версия не должна ухудшать macro Precision@5 и nDCG@5 относительно выбранного baseline. При малом N результат является проверкой прототипа, а не доказательством качества найма.

## 2. Assessment test-retest

Для каждой демонстрируемой категории сохранить минимум 20 заранее описанных профилей способностей: слабые, пограничные, уверенные. Каждый профиль проходит две разные формы одного blueprint. Ответы формируются из профиля до просмотра конкретных вариантов.

Отчёт содержит:

- долю совпавших pass/fail;
- среднюю абсолютную разницу баллов;
- долю переходов через порог;
- Spearman correlation баллов;
- распределение сложности и пропусков по item slot;
- экспертный review соответствия задания роли;
- отдельный результат для людей, если проводится добровольный пилот.

Предлагаемый, а не установленный организаторами gate: pass/fail agreement не ниже 80%, переход через порог не выше 10%, отсутствие категории, в которой одна форма систематически легче другой. При малой выборке показывать абсолютные counts.

Воспроизводимый синтетический прогон:

```bash
python scripts/simulate_assessment_validation.py
```

Он фиксирует поведение scoring mechanics при заранее заданной latent ability и небольшом retest noise. Поскольку сложность item и модель ответа заданы самим симулятором, этот результат нельзя использовать как доказательство реальной сложности, валидности содержания или качества теста на людях.

## 3. Защита от распространения

- versioned blueprint и сохранённый snapshot попытки;
- параметризованный контекст;
- случайный порядок вариантов;
- несколько взаимозаменяемых item slots;
- серверный ключ ответа;
- обязательное изменённое условие во второй фазе;
- автоматический аудит количества уникальных публичных форм на 100 seed.

Только случайный порядок ответов не считается достаточной защитой. Нужны эквивалентные сценарии и последующая калибровка по данным.
