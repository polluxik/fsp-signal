# Загрузка синтетического рынка в приложение

8 октября 2026. Источник — ветка команды `codex/synthetic-market-seed`, data commit `4a927dc`. 200 CV и 120 вакансий по 32 семействам уже подготовлены; runtime-импорта и UI в этой ветке нет. Старый дизайн описывает 48 кандидатов/4 категории; актуальный основной продукт содержит 96 учебных assessment-профилей и 8 категорий.

## План этой интеграции

1. Слить ветку без потери текущей воронки, избранного и календаря. Проверить воспроизводимость генератора и качество корпуса.
2. Добавить отдельное хранилище `synthetic_market_records` с происхождением и версией данных. Импорт разрешён только в `APP_MODE=demo`, валидирует весь корпус до записи и повторяется без дублей. Не менять аккаунты, согласия, встречи, assessment или проверенные категории.
3. Показать HR резюме и вакансии в «Рынок · демо», кандидату — вакансии. Фильтры: семейство, заявленный уровень, формат, поиск навыков/текста; страницы, просмотр полного CV и условий роли. Синтетика и отсутствие оценки видны постоянно.
4. HR может сравнить выбранную демо-вакансию с резюме: точное семейство, заявленный уровень, зарплата, формат/город, перечисленные обязательные навыки. Неполные поля означают «неизвестно». Результат — объяснение совпадений и расхождений заявленных условий, без выдачи тестового грейда или вероятности найма.
5. Существующий проверенный банк, приглашения и contact grants не использовать для этих неоценённых персонажей. Здесь нет реального работодателя, контактов и вакансии, на которую можно откликнуться. Расширение реального assessment на 32 семейства не входит в эту загрузку.
6. Проверить SQLite/PostgreSQL, повторный импорт, production gate, авторизацию, неполный/небезопасный корпус, фильтры/пагинацию/сравнение и мобильный UI. Повторить предыдущие сценарии воронки/избранного/встреч.
7. Загрузить данные в текущую демо-БД, сохранив три встречи. Учесть просьбу не пересобирать Docker: обновить нужные исходники API и готовую статику в существующих контейнерах; обычная будущая сборка должна включать корпус из Git.

## Границы интерпретации

Самоописание Senior/Lead не является подтверждённым грейдом. Заявленные навыки не становятся evidence assessment. Стаж не определяет уровень автоматически. Резюме и тексты — данные, не инструкции. Числовые примеры достижений и зарплат вымышлены; качество найма/реальную зарплату по ним не измерять. Импорт не разрешает реальные пользовательские CV или ключи в Git.

## Реализовано

Ветка слита без конфликтов и с сохранением её истории. `backend/seed_market.py` читает JSONL/taxonomy, проверяет полный корпус до записи и использует `ON CONFLICT DO NOTHING ... RETURNING id`. Подсчёт через RETURNING работает и с PostgreSQL/psycopg; driver rowcount может быть −1. Существующую запись с другим содержимым импорт не перезаписывает: для нового корпуса нужны новая версия и новые ID. Одновременный импорт двух процессов проверен на PostgreSQL.

Модель `SyntheticMarketRecord` и миграция `c918e47a25bf` после `b26c19d745ef` создают только отдельную таблицу и индекс. `backend/market.py` добавляет шесть типизированных GET-операций `/api/v1/demo-market`: метаданные, страницы CV/вакансий, полные документы и сравнение. CV/сравнение доступны HR; вакансии — вошедшим пользователям. Вне `APP_MODE=demo` маршруты возвращают 404, импорт запрещён, UI скрыт флагом `/me`.

Frontend `features/market/` показывает 20 карточек на странице, полнотекстовый поиск, направление/уровень/формат, loading/error/retry, мобильный просмотр. Применённые фильтры и страница хранятся в URL и переживают reload. Выход на другую вкладку удаляет параметры каталога. Сравнение использует canonical skill IDs и точное семейство; отсутствующие зарплата/город/формат/навыки остаются неизвестными. Текстовое сходство не заменяет обязательное условие. Нет числового match-score или записи решений в основной hiring-контур.

## Команды для другого участника

Из корня проекта, в собственном окружении и демо-БД:

```sh
alembic upgrade head
APP_MODE=demo python -m backend.seed_market
# Первый запуск: profiles=200, vacancies=120, families=32, inserted=352.
# Следующий запуск: inserted=0.
```

PowerShell: `$env:APP_MODE='demo'`, затем `python -m backend.seed_market`. DATABASE_URL должен указывать на нужную собственную БД; ключи из .env не копировать в репозиторий. Для чистого первого старта `backend.seed_demo` сам вызывает импорт каталога. На существующем стенде использовать отдельный seed_market, чтобы не менять старые учебные профили/роли.

В UI: вход HR → «Рынок · демо» → «Резюме» → «Читать резюме» → выбрать демо-вакансию для сравнения. У кандидата та же вкладка открывает только вакансии. Проверить фильтры, пустую выдачу, вторую страницу, reload и 390px. Банк кандидатов по тесту остаётся отдельным разделом.

## Проверки и текущий стенд

8 октября: PostgreSQL **216 passed** на пустой выделенной тестовой БД; SQLite **203 passed / 13 PG-only skipped**; полный Playwright **29 passed**, включая три live-Qwen; production build успешен. Генератор точно воспроизводит JSON-структуры и CSV-записи (CRLF/LF не считаются изменением данных). [Подробный отчёт](validation/synthetic-market-integration-results.md).

Корпус загружен в Compose `fsp-signal-smoke-20261007`, сайт `http://127.0.0.1:58080/`. Первый импорт создал 352 записи, повторный — 0. Проверены SHA-256 содержимого десяти прежних таблиц до/после: все совпали, включая 96 профилей, 3 приглашения, 3 contact grants и 3 встречи. Live OpenAPI совпадает с экспортом, 92 операции. Реальный браузер через Caddy открыл CV и сравнение, reload и мобильная ширина прошли.

Docker-образы не пересобирались: в существующий api скопированы нужные исходники/миграция/корпус, миграция и отдельный импорт выполнены, api перезапущен; в web скопирован локально собранный dist. Также установлен предыдущий фикс Qwen result_scope. Том БД, worker и встречи сохранены. **Эти изменения в контейнерах исчезнут при их пересоздании из старых образов**; следующий обычный запуск с пересозданием должен использовать актуально собранные образы. Dockerfile уже включает пакет data/synthetic_market_v1. Не выполнять reset/удаление volumes ради обновления.

## Что остаётся

Исходная широкая спецификация ветки — план; generic assessment/ranking по всем 32 семействам не реализованы этой интеграцией. Для настоящего допуска новых категорий нужны свои задания, рубрики и валидация. Фильтры подтверждённых компетенций внутри search snapshot, смежные verified категории, CI, публичный стенд и ASR остаются в прежнем плане. Синтетический каталог не доказывает качество реального найма.
