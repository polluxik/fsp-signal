# Signal v2 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Улучшить существующий обратный найм: конкретная роль, явные предпочтения, доказательства по задаче, безопасное согласие и измеримый следующий шаг; подготовить честно проверенную защиту ФСП и товар B2B-пилота.

**Architecture:** React/TypeScript и FastAPI остаются одним приложением. Расширяем существующие HiringNeed/Invitation/ContactGrant, добавляем immutable RoleVersion, RoleDecision, ProductEvent и опциональный HiringConversation. Matching и все права остаются на сервере; новые функции подключаются небольшими доменными модулями и typed DTO.

**Tech Stack:** Текущие React/Vite/TypeScript, FastAPI/Pydantic/SQLAlchemy/Alembic/psycopg, pytest, PostgreSQL 17.11 из Compose, SMTP/Mailpit; Playwright — только dev-проверка браузера с зафиксированным lock.

**Spec:** [2026-10-05-signal-v2-design.md](../specs/2026-10-05-signal-v2-design.md). Также читать исходные R01–R25 в [PRODUCT_SPEC.md](../../PRODUCT_SPEC.md) и [implementation-status.md](../../implementation-status.md).

## Global Constraints

- Рабочий cap — 105 человеко-часов (3 ×5 ×7 продуктивных часов). H1 не вытесняет H0, оценку и сдачу.
- Четыре категории: backend/frontend × junior/middle; русский UI; RUB/month/gross. Наймовый пилот 18+ и opt-in.
- Роль свежая 14 суток; default invitation expiry 7 суток; SLA 24/48/72 часа — elapsed UTC, не бизнес-календарь.
- Исходные assessment rules: 20 минут, ≥70/100, ≥50% каждой группы, correct mutation, 72 часа повтор, 30 дней смена, максимум 3 попытки за7 дней; провал не понижает прежний грейд.
- Legacy данные не дополнять выдуманными подтверждениями, прошлые приглашения не привязывать к сегодняшней role version.
- ContactGrant привязан к существующему employer user, не ко всем компаниям/рекрутерам; никакого автоматического раскрытия.
- Salary floor, блок-лист, summary/полный CV и ответы/ключи теста не входят в employer-public DTO.
- Новых runtime dependencies/сервисов для H0/H1 не требуется. Миграции обязательны; `create_all` не заменяет Alembic.
- H0/H1 demo ≠ real-data release. Симулятор H1 только synthetic. Synthetic events исключены из real metrics.
- Каждый task заканчивается проверяемым deliverable и scoped commit во время реализации; не включать чужие/несвязанные изменения ресерча автоматически.

## Review Focus

1. Candidate preference или роль изменились между поиском/отправкой/accept: устаревшее действие должно дать conflict, а не раскрыть контакт. Проверки T3/T5/T6.
2. Одновременные accept/reject/withdraw/expire или повтор create: одна запись/переход/grant/event, PostgreSQL-проверка. T6.
3. Несколько grants пары employer/candidate: company-wide revoke/block закрывает все, повтор accept не восстанавливает доступ. T3/T6.
4. Fixture без AssessmentAttempt, declared стек или unknown компетенция: нельзя выдумать проверенное действие/слабость человека. T4/T5.
5. Stale/paused role, неизвестное условие, перенос встречи и повтор confirmation: не публикуем неверный match и не считаем несостоявшееся интервью. T2/T8/T11/T12.

## Контракты, которые фиксируем до реализации

В `backend/schemas.py` добавить:

- `CandidatePreferencesIn`: expected_version≥1; salary_min_rub nullable≥1; allowed_work_formats (1–3 enum значений); allowed_cities/excluded_industries/preferred_stack/preferred_tasks; max_take_home_minutes nullable 0–240; available bool; adult_hiring_confirmed bool. Блок-лист изменяется отдельной командой.
- `RoleCardIn`: существующие title/description/category/competencies/stack/salary, конкретный work_format, work_city nullable, first_30_days, industry nullable, interview_steps (1–5 `{title, duration_minutes:1..240}`), take_home_minutes 0–240, response_sla_hours 24/48/72, employer_contact, active_headcount_attested bool. Gross/month/RUB фиксированы.
- `CompatibilityCheck {code, status:pass|unknown|fail, public_text}`; `CompatibilityReport {status:compatible|needs_clarification|incompatible, checks, preference_version, role_version_id, compatibility_version:'compat_v2'}`. Employer-проекция исключает private values; score version независима.
- `PublishRoleIn {expected_version, active_headcount_attested, discoverable:bool}`: active private роль допускает собственный поиск/приглашение, candidate discovery требует discoverable=true.
- `EvidenceCard` и `MatchExplanation {reasons, gaps, agenda}`, как в §§9–10/21 spec. Evidence ref содержит source ID/version; сообщения работодателя отдельно.
- `InvitationV2In`: existing InvitationIn + nullable role_version_id/inline_role_card + evidence_ids. Новое приглашение требует одну из этих форм; historical read/accept legacy остаётся отдельно.
- `AcceptInvitationIn {expected_terms_hash, expected_preferences_version}` для v2. Legacy active invitations показывают свои существующие условия и проходят отдельную проверку, без выдуманного нового role snapshot.
- `ConversationCommandIn {expected_version}`; `TimeProposalIn` дополнительно starts_at aware UTC, duration_minutes 1–240, timezone IANA; `ConfirmTimeIn` дополнительно schedule_version; `HeldConfirmationIn` дополнительно schedule_version и held bool. Все command types используют expected_version из base.
- `MetricReport {data_mode, from, to, as_of, counts, ratios, limitations}`: при нулевом знаменателе ratio=null.

Нормализация: strings trim/casefold для словарных сравнений; город профиля не равен allowed city preference. Неизвестная industry/location — unknown при требующем её hard constraint. Все новое free text ≤2 000, employer comment в invitation сохраняет legacy лимит 1 500. Typed outputs новых routes используют `response_model`.
